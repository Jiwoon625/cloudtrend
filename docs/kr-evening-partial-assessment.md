# 한국 저녁 스크리닝: 계산된 판단과 KRX 대기 분리

## 목적

KRX의 해당 거래일 자료가 다음 영업일 08:00 KST부터 조회되는 정상적인 저녁 공표 대기 중에도, 저장된 가격·거래량·기술점수와 조건별 판단을 확인할 수 있게 한다. 이는 표시 변경이며 매매 규칙 변경이 아니다.

## 표시

- 대시보드 `계산된 국내 조건별 판단`: 전체 주식·ETF를 종목/시장 검색과 20행 페이지 단위로 조회한다. 기존 진입 준비/EXIT 집계는 그대로 둔다.
- 주식 스크리너: 현재 기술점수와 기술 등급, 전일 대비 8.0점 신규 돌파, 기술청산 조건, KOSPI 확인일 점수 유지·RSAccel·시장국면 및 기존 확인 사유를 표시한다. 기술 신규 돌파 프리셋은 실제 진입 후보와 분리한다.
- 실제 포트폴리오: 보유종목만 추린 같은 근거를 보여준다. 이미 보유 중인 종목의 추가 진입 제한은 유지한다.
- ETF 스크리너: 기존 적격 종목과 `현재 KRX 대기 + 전략 대상`을 기본 표시한다. 확정 부적격·비대상은 기본에서 제외하고 전체/데이터 점검 필터에 유지한다.
- ETF 점수는 현재 전략 버전, 기준일 및 항목별 근거를 확인해 표시한다. 가격 없음/이력 부족에 동반된 0은 `산정 불가`, 실제 관측된 0은 0으로 표시한다. 전일 M0는 날짜와 함께 과거 참고로 표시한다.

주식 예시 문구:

- `기술점수 8/10 · A등급 (기술 기준)`
- `8.0점 신규 돌파 충족 · 5.5 → 8`
- `기술청산 조건 없음`
- `자료 확인 대기: 기준일 시가총액 미확인 · 판단 보류`
- `최종 진입 미확정 · 필수 자료 확인 대기`
- 확인된 RS/시장/유니버스 실패는 `확인된 조건 미충족 · 신규 진입 제외`로 표시하면서 시가총액 대기도 별도로 남긴다.

## 변경 경계

- 완료된 `AnalysisResult`와 기존 `etfStrategy` 필드만 읽는다. 원천 공급자 조회나 새 점수 계산은 없다.
- 대시보드의 기존 projection sidecar 버전만 변경한다. 기존 완료 결과를 다시 투영하므로 스크리닝 재실행 없이 새 표시 근거를 읽을 수 있다.
- 엔진의 eligible/onset/확인 상태, 주문 미리보기, 자동매매, Shadow의 진입 시점, 과거 스크리닝 이력과 실제/전략 원장에는 변경이 없다.
- 실제 보유의 기술청산은 기존 `getHeldOperationalExitSignal`로 표시한다. 보유기간 만기 등 원장 수준 청산 판단은 기존 원장에 남긴다.
- 날짜가 오래되거나 연속 거래일 근거가 불충분한 경우 현재 돌파·청산을 만들어 표시하지 않는다.
- KRX 수집기와 Colab 코드는 변경하지 않는다.

## 검증

- 대시보드·확인·ETF·표시 회귀: `npx vitest run --config vitest.dashboard.config.ts`
- 포트폴리오 원장 회귀: `npx vitest run --config vitest.portfolio.config.ts`
- 스크리닝/포트폴리오 신선도: `npx vitest run --config vitest.portfolio-freshness.config.ts`
- 원장 UI 편집 안전성: `npx vitest run --config vitest.ledger-ui.config.ts`
- 변경 파일 ESLint, `git diff --check`, production build

회귀에는 614종목의 579 PENDING/35 FAIL 합성 사례, 시총 대기 중 5.5→8점 보유종목의 기술청산 없음, 음수 RSAccel과 RISK_OFF의 독립 탈락 표시, 보유종목 상향 청산 우선, 결측/실제 0점 구분, 과거 날짜와 비연속 거래일, 새 projection 버전 재사용, ETF 4개 필터의 ready/FAIL/incomplete/pending 구분, 반복 검색·시장 전환·페이지 전환을 포함한다.

전체 `tsc --noEmit`은 기준 커밋에 이미 존재하는 오류 때문에 실패한다. 동일 커밋의 깨끗한 worktree와 오류 출력을 비교해 신규 오류가 없는지 확인한다. 로컬 Chromium은 환경의 socket 권한 제한으로 시작하지 못했으므로 실제 브라우저 화면 QA는 완료되지 않았다. SSR 및 컴포넌트 이벤트 검증과 production build는 별도 수행한다.

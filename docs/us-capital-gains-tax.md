# 미국주식 양도소득세 참고 추정 v1

확인 기준: **2026-10-03 Asia/Seoul**. 계산 버전 `KR-US-CGT-2026-10-03-v1`.
소득세법(시행 2026-07-01, 법률 제21221호), 시행령(대통령령 제36343호),
지방세법(법률 제21308호)을 기준으로 한 일반형 참고 계산이다. 신고서·확정 세액 계산기가 아니다.

## 적용 범위

- 일반 한국 거주자 요건을 확인한 일반계좌의 과세대상 미국 직접상장 주식 및 투자회사형 ETF
- 과세 국내주식은 법적으로 합산 대상일 수 있으나 v1은 USD 표시 해외주식의 기본 20% 국세율 계산만 지원한다. 과세 국내주식이 함께 있으면 원화 취득원가·손익 및 공제 배분 어댑터가 준비될 때까지 산출하지 않는다
- 비과세 국내상장 소액주주 장내손익, 국내상장 해외 ETF의 배당소득, 배당·분배금, 미실현손익, 파생상품 제외
- ISA·미확인 계좌는 이 풀에서 분리한다. 과거 거래의 증권사/계좌를 추정 배정하지 않는다
- 다른 세율이 섞이거나 특수구조 상품·PTP·특정 부동산주식이면 법정 배분을 지원하지 않으므로 산출하지 않는다
- RIA·환헤지 등 특례, 외국납부세액공제, 세액공제·감면과 신고서 절사는 구현하지 않는다
- 실제 거주요건은 별도 확인 대상이다. 모델은 명시적인 거주자 가정을 쓸 수 있다

## 산식 및 시간

연간 원화 실현손익 = 매도대금(USD × 매도 결제일 환율) − 각 취득분 원가(USD × 해당 매수 결제일 환율) − 확인된 필요경비.

`과세표준 = max(0, 연간 실현손익 − 2,500,000 KRW)`

국세 20%와 지방소득세 2%를 별도 계산한다. 정확히 250만 원이면 0원이며 **초과분**에 통상 22%다.
다른 계좌/증권사를 합친 동일 소유자에게 연간 기본공제를 한 번만 적용한다. 손실은 해당 연도 내에서 통산하고 다음 연도에 이월 공제하지 않는다.

귀속연도는 **매도 결제일**로 정한다. 거래일·주문일·현재 환율로 대체하지 않는다. 실제 원가는 증권사 세무 보조자료와 대사하고 원가법을 명시한다. Shadow는 명시한 모형 원가법을 사용할 수 있다.

국세 신고기한은 통상 다음 해 5월(휴일 이연), 지방소득세는 국세 신고기한으로부터 2개월 이내다. 이 기능은 신고·납부를 수행하지 않는다.

## 비용과 세금 유보액

- 실제 비용은 확인된 실지출 증빙만 쓴다. 수수료 면제·ISA 혜택을 자동 추정하지 않는다
- `grossCostUsd`와 `grossProceedsUsd`는 수수료 포함 금액이 아니다. 실제 인정 필요경비만 각각 원화로 한 번 더한다/뺀다
- 슬리피지가 이미 체결가격에 포함되었다면 별도 필요경비로 다시 공제하지 않는다
- 기존 A0/A2/B3의 편도 0.25% 비용과 동결 이력은 수정하지 않는다
- 신규 연구의 왕복 0.30% 비용도 연간 양도세와 별도다. 합산 모형 비용을 전부 세법상 인정경비로 간주하지 않는다
- 현재 연도 세금 유보액은 실현손실이 생기면 감소할 수 있다
- 1월 1일에 전년도 미납세금은 사라지지 않는다. 원장 시작 이전 부채도 출처 있는 기초값으로 보존한다
- 납부가 이미 NAV에 반영되었으면 다시 차감하지 않는다. 원장 밖 납부는 확인된 당시 USD 지출액을 사용한다
- 미납세금 KRW의 USD 표시에는 **NAV 평가일의 별도 환율**을 사용한다. 초기 자본 환율을 미래 결제환율로 재사용하지 않는다
- 세후 NAV는 보고용 추정치다. 원래 현금·보유·신호·주문·기록을 변경하거나 세금 납부/재투자 효과를 시뮬레이션하지 않는다

## 자료 계약 및 현재 한계

`src/lib/engine/usCapitalGainsTax.ts`의 `usTaxEvidenceSchema`가 유효한 거래·계좌 범위, 원가/인정경비, 결제환율, 납부내역, 이전 부채, 평가환율과 출처를 요구한다.
모든 실제 전략/계좌는 하나의 `ACTUAL_OWNER` 풀로 전달한다. A0/A2/B3와 향후 별도 버전은 각각 독립 `COUNTERFACTUAL:<strategyId>`를 사용한다. 통합 자본배분 실험은 하나의 시나리오 풀로 전달해야 한다.

실제 자료는 증권사 확인 원가법만 허용한다. 모델은 `FIFO_MODEL` 또는 `MOVING_AVERAGE_MODEL`을 명시할 수 있으나, 이 모듈은 매칭을 추정하지 않는다. **각 매도의 확인된 취득분 배분**을 입력해야 한다. 이전입고·분할·합병·증여로 원가 계보가 끊긴 경우 완전성/대사 확인을 할 수 없으므로 미확인으로 남긴다.

- 전체 계좌/기간이 확인된 경우 `ESTIMATE`
- 계산 가능한 등록 거래만 있으면 `PARTIAL`, 화면에 “등록 거래 기준 · 전체 계좌 세금 미확인” 표시
- 결제환율·원가·필수 비용·거주요건·계좌 분류 등이 없으면 `UNAVAILABLE`, 금액 `null`
- 이전 부채만 미확인이면 검증된 당해 연도 세액은 표시하고 누적 미납 유보액·세후 NAV만 `null`
- 연간 KRW 세액은 계산 가능해도 0원이 아닌 유보액의 평가환율이 없으면 세후 USD NAV는 `null`. 독립적으로 확인된 유보액 0원은 환산이 필요 없어 세후 NAV를 표시한다
- 단순히 등록 매도가 없다는 이유로 전체 세금을 0으로 표시하지 않는다

UI는 기존 자료에서 USD 손익 × 22%를 계산하지 않는다. 실제 원장은 검증된 결제일·세무 환율·원가 및 완전성 증거가 없으면 계속 **미확인**이다.

### 연결된 Shadow 읽기 전용 경로

`UsModelTaxEstimatePanel`은 보유/NAV/주문 조회와 별도 쿼리로 세금 원천을 확인한다. 새 인증 서버 함수는 `getUser`로 소유자를 확인하고 모든 테이블/Storage 조회를 해당 사용자로 제한한다. 새로운 자격증명·DDL·쓰기 API는 없다.

1. 동결된 전략 레지스트리, 첫 현금 전용 $100,000 스냅샷, 시작일부터 기준일까지 **전체 페이지**의 스냅샷·실제 발생한 모델 체결·완료 마커를 확인한다
2. 각 동결 일별 입력 파일의 데이터 해시, 규칙 버전, 정규장 완료 여부, 실패 종목 0건, 이전 거래일 연결을 대조한다. 스냅샷과 완료 테이블 양쪽에 날짜가 빠진 경우도 연결 검증으로 거부한다
3. 매일 모델 체결 합계를 현금·보유수량·기존 편도 비용·NAV와 대사한다. 누락/중복/부분 초기화는 완전한 이력으로 취급하지 않는다
4. 전체 매수가 확인되고 매도가 없는 닫힌 가상 모델은 연간 실현소득/세금 0원을 정당하게 표시한다. 실제 계좌에 매도 기록이 없다는 것과 구분한다
5. 매도가 있으면 FIFO 취득분을 배분한다. 각 체결의 **출처가 있는 세무 결제일과 해당 환율**을 제공해야 숫자를 표시한다. 라이브 결제/환율 공급자는 아직 연결되지 않아 현재 매도 포함 모델은 구체적인 미확인 사유를 표시한다
6. 기존 합산 거래비용을 전액 인정 필요경비로 가정하지 않는다. 첫 모델 추정은 비용 공제를 추가하지 않는 보수적 FIFO 모형이라고 화면에 표시한다. 실제 비용이 0이라는 뜻이 아니며 기존 세전 비용을 변경하지 않는다

일별 원본 파일 읽기는 최대 4개 동시 요청으로 제한하고, 인증 후 소유자·날짜·완료 해시별로 **작은 불변 증거 메타데이터만** 제한된 캐시에 공유한다. 전체 원본/토큰은 캐시하지 않는다. 과거 스냅샷도 필요한 상태 필드만 JSON 경로로 읽는다. 세금 조회가 오래 걸리거나 실패해도 보유/NAV 화면은 먼저 반환한다.

세금 projection은 조회 메모리에서만 생성되며 기존 `us_portfolio_snapshots`, 실제 원장, 모델 현금·체결·완료 이력은 수정하지 않는다. `sourceLedgerRevision`/`sourceLedgerDigest`는 실제 읽어 검증한 원천 전체와 타이밍 증빙의 SHA-256에서 생성한다. 동일 날짜/NAV여도 증거가 바뀌면 식별자가 바뀐다.

### 남은 연결과 최소 입력

실제 원장은 선택적 `document.taxEvidence`의 `sourceRevision`, 정규화 체결 원천 비교값 및 검증된 `evidence`를 소비할 준비만 되어 있다. 증권사 양도소득 보조자료 업로드/대사/저장 어댑터는 미구현이다. 실제 숫자에 필요한 최소 자료는 해당 연도 해외주식 세무 계산 상세(이전 취득/이전입고 원가 포함)와 계좌 범위다. 과거 미납·납부 여부는 누적 세후 NAV에만 추가로 필요하다. 기존 수수료·세금 증빙 값을 덮어쓰지 않는다.

모델의 다음 단계는 `UsModelTaxTiming` 공급자다. 필요한 필드는 체결 키, 세무상 결제일, 그 날짜의 USD/KRW 기준환율 및 환율/결제일 출처, 일반 해외주식/투자회사형 ETF 분류, 별도의 NAV 평가환율이다. 시간대·법적 적용일과 고시일은 구분해야 하며 한국 휴일에 이전 고시를 임의 이월하지 않는다.

- 기존 collector의 `fx_usdkrw`는 일반 환율 응답의 숫자를 추출한 값으로, 세무 적용일/환율 종류를 증명하지 않는다. 2026-10-02 초기 자금 환율 역시 다른 날의 결제환율을 대신하지 않는다
- [한국수출입은행 공개 환율 서비스](https://www.data.go.kr/data/3068846/openapi.do)는 후보 공급자다. 현재 공식 도메인은 `oapi.koreaexim.go.kr`이며 인증키 설정과 세무 기준환율/적용일 대사가 필요하다. 이 변경은 키 발급·설정을 하지 않는다
- [미국 T+1 안내](https://www.dtcc.com/initiatives/accelerated-settlement/US-T1)에 맞는 **주식 결제** 달력과 한국 과세 결제일 정의를 검증해야 한다. 기존 `ModelCalendar`는 정규 거래일 달력이라 그대로 결제일로 쓸 수 없다
- 새로운 0.30% 왕복 모델 버전에는 별도 동결 모델 run/receipt 어댑터가 필요하다. 기본 세금 엔진은 독립 풀/초기자금/납부 처리를 지원하지만, 이번 읽기 경로는 기존 A0/A2/B3 세 전략을 대상으로 한다

다음 완료 조건은 (a) 실제 모델 원천으로 읽기 전용 projection 재조회, (b) 공개 FX/결제일 증거를 갖춘 매도 사례의 비영 세액 검증, (c) 실제 증권사 자료와 별도 대사다. 합성 테스트만으로 이 세 항목을 완료했다고 표시하지 않는다.

## 검증

`npx vitest run --config vitest.us-tax.config.ts`

임계값, 연간 순손익, 계좌 합산, 손실 환입, 전년 부채, 결제연도 경계, USD 손실/KRW 이익, 비용 중복 방지, 누락값, 독립 모델/실제 풀, 납부액 중복 방지, 스냅샷 불변, 원천 revision, 오래된 평가일, UI 표시를 검증한다. `US tax estimate check` CI는 인접 실제원장·Shadow 검사와 build도 실행한다.

# Exact reviewed adjusted-source MODEL recovery

This manual-only workflow is separate from ordinary collection/screening. It never writes an actual portfolio. It preserves every original completed model session and the original integrated evidence, and does not describe later-known data as historically available.

## Two independent authorities

1. `PLAN` consumes one owner-private, independently hash-pinned operation input manifest. Its fixed references bind the already stored preparation, capture/read-plan, seven registries, the dated next US input, current active source order/metadata, and actual/model invariants. It reproduces the preparation under the **same admitted runtime**, then calculates the five adopted books for two consecutive dates, two integrated continuations, the legacy KOSPI copy-on-write continuation, and a masked correction based on current raw row lineage. It appends one private evidence-only plan. Candidate authority-shaped objects inside that plan are **not provisioned approval**.
2. `APPLY` requires a separate independently reviewed owner-private approval digest binding that entire plan, runtime, exact output hashes, retrospective authority, source-vintage successor, legacy plan, and source correction. A missing, self-declared, conflicting or changed authority fails closed.

Dispatch inputs are opaque hashes, never owner IDs, symbols, prices, JSON or credentials. Raw reports stay private and ephemeral; the workflow does not upload Actions artifacts. Public summaries contain static categories, hashes, counts and booleans only.

## Honest clocks and preserved history

Ordinary publication availability rules are unchanged. Only a dedicated exact private retrospective authority can supply later-known observations. It records the original FINAL source activation, provider capture and private evidence storage as distinct event types, alongside the modeled decision/availability clocks. Derived observations are explicitly not a newly registered collector FINAL source. All durable prepared entries retain the provenance in each run's publication without adding unsupported top-level RPC fields.

The integrated completed day is compared on every economic session input except the precise source-hash field. Its original evidence and output remain unchanged. The new integrated outputs have an immutable, hash-linked execution-provenance receipt containing their exact state identities before any model append. No blanket economic-field exclusion is used.

The private vintage successor retains the old receipt/registry byte-for-byte and only authorizes finite exact old/new bar pairs. KR cumulative economic records and integrated history are checked; ETF and confirmation historical executed-exposure exclusion uses the authenticated frozen monotonic fee/entry-counter invariants, not a fictitious scan of missing daily records.

## Mutation boundaries and retries

Before provisioning authority or writing a model, the runner validates all model prefixes, legacy virtual replay and staged-source identity. Adopted/integrated appends use the existing atomic predecessor and immutable-date RPC. A retry accepts only the exact approved contiguous prefix. It never rewinds or overwrites completed records. Every original model row remains hash-bound; both actual portfolio rows are checked in full before and in `finally`, including failure/partial outcomes.

All admitted legacy journal writers share the entire-job `kospi-prospective-shadow` concurrency group. The wrapper verifies its named main/manual workflow context. This is workflow serialization, not a database CAS; no atomicity is claimed for a bare Storage projection write. Legacy retries replay from the original captured predecessor and accept only matching reviewed intermediate snapshots/projections.

## History source staging is not activation

The runner creates only a deterministic private blob and `valid` source row. It never calls source activation, removes a blob, invalidates a source, retires an active source or synchronizes legacy/actual portfolio tables. Uncertain writes are resolved by exact readback; they are not blindly repeated or rolled back destructively.

The private model-stage receipt contains the blob SHA, Storage generation, full staged-row hash, and expected active-roster hash. The result is **model restoration with source activation pending**, not complete recovery.

Activation is a separately reviewed transaction through the existing authorized database path. It must lock the planned source row and acquire the same existing owner/source-type advisory lock used by the normal activation function, compare the complete expected active roster under that lock, call the existing merge activation function, verify preserved old rows and effective latest PRELIMINARY horizon, and roll back the entire transaction on any mismatch. No new schema, RPC, policy or lock bypass is required. A collector racing to activate first makes the comparison fail before activation. An independent readback is required before claiming durable source handoff complete.

The history CSV copies current effective raw rows and changes only the approved OHLCV/tagged engine-proxy cells. Newer rows and independent observations are retained. Extra non-engine monetary proxy columns are disclosed as retained; no claim of all-column cash consistency is made. The source has `HISTORY_ONLY` metadata and no fabricated `krPublication` FINAL declaration.

## Release/execution gates

- Independent exact-tree review, synthetic fault/retry tests, TypeScript/build/lint, and regenerated/admitted runtime manifests.
- Exact remote head/tree CI and deployed identity; no formal account APPROVE is implied by local technical review.
- First durable preparation occurs only after the final runtime is admitted. A different runtime cannot reuse/replace an immutable preparation receipt.
- Independent review of actual private PLAN results, followed by one explicit dispatch and fresh owner/source/model invariants.
- Deployed append-function contract verification and no conflicting operational collection/final publication.
- Separate transactional source activation and final actual/model/source readback.

A clean public-code build alone is not operational recovery approval or proof that the private comparison succeeded.

### Dedicated cache-priority continuation approval

The ordinary `kospi-final-retrospective-approval-v1` continues to require a true strict
completed-boundary equivalence result. The alternative
`kospi-priority-continuation-approval-v1` adds the exact
`boundaryMode: PRIORITY_ONLY_PREDECESSOR_CONTINUATION` and `boundaryProofHash`.
It is admitted only for a false strict result with a successful independently reviewed,
versioned three-start exact-target certificate. The full preparation, plan, runtime, immutable
anchor and all output pins remain required. PLAN creates only a candidate approval shape.

APPLY resolves the certificate from the exact captured objects, recomputes the full proof and
matches its output bodies before any live mutation. It then uses the existing original-anchor
simulation, immutable-prefix/partial-retry checks, shared legacy writer exclusion and exact
append/readback protocol. It never rewrites the completed predecessor or substitutes a
counterfactual state into the live store. Missing, contradictory, unknown or rehashed-but-invalid
proofs fail closed before writes. No partial recovery scope or catch-and-continue path is added.

# 기초지수 전용 백엔드 연결 (진단용)

## 범위와 완료 기준

기존 Drive ETF 정본과 KRX 저장자료에서 기초지수만 추출하고, 별도 백엔드가 실제 활성 원천을 읽어 비교 MA60를 계산한다. 저장만 하는 기능이 아니다. `/data-status#underlying-index-diagnostics`의 `기초지수 비교 계산`으로 실행한다.

**현재 매매 모델 연결은 하지 않는다.** 이 경로는 전략 적격, 진입·청산 신호, 비주식형 ETF의 매도 규칙, 과거 스크리닝, Shadow, 실제 원장을 변경하지 않는다. 현재 모델의 MA60와 진단용 MA60는 별도 값이다. `activeMa60`는 공유된 최근 60개 관측일에서 활성 원천을 재계산한 값이며, 저장된 스크리닝 MA60라고 표현하지 않는다.

## 저장·권한

- 기존 비공개 `cloudtrend-data` 버킷에서 인증된 동일 소유자의 `results/ingestion/underlying-index/<sha256>.json`만 사용한다.
- 서버는 `auth.getUser`로 사용자를 확인하고 소유자를 직접 도출한다. 외부 owner/path/bucket 입력은 받지 않는다. 서비스 역할 키, 새 인증정보, 스키마나 권한 변경이 없다.
- 검증자료의 해시는 `underlyingIndexSupplementRelease.ts`에서 고정한다. Gzip 전송을 해제한 **원시 바이트**의 SHA256을 먼저 대조하고, 그 뒤 엄격한 UTF-8 및 필드 스키마를 검사한다. 압축·해제 크기 상한이 있다.
- 파일은 새 불변 객체로만 저장한다 (`upsert:false`). 동일 파일은 재사용한다. 오류/불확실한 쓰기 뒤에는 한 번 읽어서 정확히 같은 바이트인지 확인하며 무작정 재전송하지 않는다.
- 일반 `analysis_source_files` 등록, source activation, mutable latest pointer, 정규 CSV 업로드를 사용하지 않는다. 기존 결과 파일도 덮어쓰지 않는다.

## 불변성과 검증

1. 활성 원천은 기존 로더로 순서대로 읽고 22개 파일의 등록 바이트 해시를 재검증한다. 계산 후 활성 집합을 다시 확인해 경쟁 변경이면 결과를 폐기한다.
2. 기존 파서의 별도 KRX 참조 파서를 그대로 사용한다. 원래 엔진 파서·가격 우선순위·source 등록 코드는 변경하지 않는다.
3. 가격 데이터셋은 입력일 뿐이다. 전후 전체 데이터셋 해시가 같아야 결과를 반환한다. OHLC, 거래량, NAV, 관측 플래그, 출처, 가격행, 종목·분류는 추가·수정·삭제하지 않는다. 없는 가격행을 만들어 넣지 않는다.
4. 지수 계산은 별도 Map에서만 이루어진다. 기존 원본 양수 값은 보존한다. 기본적으로 출처·이름·중복 관측의 값이 맞지 않으면 해당 ETF 전체를 격리한다. 아래의 명시적 사용자 선택 목록만 별도 진단 계산에서 예외로 적용하며 원본값은 수정하지 않는다. 향후 날짜의 이름·출처 변경도 같은 검증을 거친다.
5. 최근 60개 **관측일** 중 하나라도 결측이면 MA60는 null이다. 유효한 값만 골라 60개를 만드는 방식, NAV·ETF 가격 대체, 보간, 미래 값 사용은 금지한다.
6. 순수 계산과 실제 백엔드 reader는 저장 호출이 0회다. 표준 스크리닝 실행·게시·Shadow replay·portfolio sync를 호출하지 않는다. 동일 소유자의 동시 요청은 진행 중 계산을 공유한다.

## 원천 및 시간적 한계

- 2026-10-16까지의 기존 자료, 현재 1,176 ETF, 최근 66개 관측일만 포함한다. 정본 전체나 OHLC·NAV는 업로드하지 않는다.
- 4개 Parquet는 각 collector manifest의 바이트 해시와 일치한다. 7개 KRX JSON 캐시는 보관 파일 바이트 해시를 기록한다. 캐시 자체에 별도 발행기관 서명/체크섬이 있다는 뜻은 아니다.
- 원본 파일의 빈티지 및 해시는 유지한다. 캡처 시각을 알 수 없는 캐시는 null이며 발표시각을 지어내지 않는다. 연결자료의 `availableFrom`은 신규 진단 빈티지 시각이다.
- 독립 index ID·통화·산식 인증은 아직 없다. 동일 ETF·KRX 필드·이름·중복값 대조를 통과해도 진단용 참고값이지 전략 인증은 아니다.
- 실제 보강 관측 구간(현재 66일)의 지수명이 단일해야 한다. 해당 구간의 모든 양수 활성 중복관측은 같은 지수명·KRX_ETF 출처여야 하며, 최근 60일 밖의 첫 6일도 예외가 아니다. 최근 계산 구간의 추가 관측도 같은 검증을 거친다. 전체 장기자료의 과거 이름 이력은 보존하되 현재 관측 구간에 포함되지 않은 과거 TR/PR 변경만으로 격리하지 않는다. 실제 보강 구간에서 TR/PR 등 이름이 바뀌면 계속 격리하며 서로 다른 지수 계열을 이어 붙이지 않는다.
- 관측 달력이며 거래소 공식 연속 세션 인증이 아니다. 원본의 `complete=false`, total-return/survivorship 검증 미완료 상태는 바꾸지 않는다.
- 새 빈티지를 이전 기준일의 거래 의사결정이나 과거 Shadow에 넣을 수 없다. 모델에 연결하려면 영향 종목·규칙·적용 시작시점·별도 빈티지를 검토해야 한다.

## 재현 및 롤백

추출 스크립트는 로컬 원본만 읽는다. `--source-dir`, `--roster-file`, `--output`, `--available-from`, `--cutoff-date`를 명시한다. 네트워크/업로드/수집 기능이 없다. 생성물은 저장소에 커밋하지 않는다.

테스트: `npx vitest run --config vitest.underlying-index.config.ts`.

롤백은 release의 `enabled:false`로 해당 전용 소비만 끈다. 기존 자료를 삭제하거나 이전 가격을 다시 올리지 않는다. 보관 객체는 감사 재현용으로 남긴다.

## 명시적 사용자 선택 보강 빈티지

2026-10-17 승인 범위는 311종의 884개 충돌 관측을 별도 기초지수 계산에서 보강자료 우선으로 사용하는 것이다. 새 불변 자료에 `approvedPreference` 목록을 포함하고 전체 바이트 해시를 고정한다. 기존 보강 파일과 활성 원천은 삭제하거나 덮어쓰지 않는다. 이 선택은 지수 최종성·공표시각·PIT·일률적 하루 지연을 인증하는 것이 아니다.

목록에는 승인시각, 기존 보강파일 해시, 활성원천집합·dataset·기준일, 종목·날짜·기존값·선택값·지수명·출처해시가 있다. 종목/날짜 중복, 목록과 실제 보강자료 불일치, 추가 종목, 미래 승인시각을 거부한다. 설치 시 활성원천집합이 다르면 설치하지 않는다. 계산 직전 활성원천집합·dataset·기준일·각 기존값/지수명/출처가 다르면 우선 적용을 중단한다. 새 수집자료가 들어오면 자동으로 승인 범위를 확대하지 않고 새 대사가 필요하다.

계산은 승인된 날짜에서만 별도 Map의 보강값을 우선 사용한다. `activeMa60`와 원본 dataset, `conflicts`는 유지하고 `approvedPreferenceDates`/`userSelectedVintage` 및 원본·선택값 전체 승인목록을 JSON 감사정보로 제공한다. 사용자 선택 자료가 적용된 `diagnosticMa60`는 화면에 명시하며 매매 엔진이나 Shadow/실제원장에 전달하지 않는다. 60일이 완전한 301종만 추가 계산하고 10종은 결측을 임의로 채우지 않는다. 자료 불명 265690은 승인 목록 밖이며 격리 유지다.

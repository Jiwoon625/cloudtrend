# ETF detail: dated M0 and actual underlying history

## Display contract

- The current-day M0 and operational/entry decision remain unchanged. A pending KRX batch keeps today's M0 unavailable.
- A separate `전 거래일 M0` reference is shown only when the exact prior market session has complete dated scoring evidence. Its tooltip identifies a dated reconstruction under the current ETF policy, not an immutable copy of a previously published screen or an entry confirmation. Missing prior-day evidence does not fall back to an older score.
- M0 is the actual weighted total: technical 62.5%, priority 7.5%, health 15%, environment 15%. Historical peer and domestic-sector inputs are evaluated at each point's own date. No operational signals are generated by the chart.
- Prices, volumes, historical M0, and underlying observations remain available before the 2026-10-12 operational start. Missing values are null gaps, never zero or forward-filled. The fast price-only phase uses canonical observed bars and the same gaps as the complete ETF bundle.
- The underlying chart uses the dated KRX ETF underlying-index field, never ETF price, NAV, KOSPI, or a guessed proxy. Each point retains its original index name. Identity changes break the drawn line; MA60 requires 60 consecutive complete market-session observations with one known identity. Missing names or values leave MA60 empty. The last observed index date is shown separately from the ETF screening date.

## Loading and caching

ETF charts use the existing authenticated server RPC, immutable input fingerprint/result digest, owner-scoped gzip storage, recent bucket cache, request coalescing, five-minute server-context reuse, and React Query revision isolation. The RPC proxy remains statically imported to avoid requesting a retired release chunk.

`etf-chart-v2-m0-underlying` separates both ETF M0/index bundles and safe `etf-prices` bundles from legacy technical-score/generic price caches. Recent 120-session bundles are prepared by existing screening/repair warmup. Full history is requested only after selecting `전체 기간`. Recent peer calculations are date-lazy and do not precompute the entire peer history. Price loading remains independent of score loading and explicit retry remains available.

The existing display-only reference parser retains dated `etfUnderlyingIndexName` and value provenance. The frozen operational parser, strategy module, ledger manifests, and SQL contracts remain byte-for-byte unchanged. A separate historical display evaluator mirrors private math, imports shared public scoring helpers, and has explicit dated parity tests against the untouched operational engine.

## Reproducible local profile

Run `npx vite-node --config vitest.charts.config.ts --script scripts/profile-etf-instrument-charts.ts`.

A synthetic 1,250-session fixture with 240 stocks and seven ETFs measured local computation plus in-memory compressed storage. These are not production end-to-end or network timings. Buckets can contain different symbol counts, so these measurements do not establish that every ETF is faster than every stock.

| Result                              | Cold local ms | Warm local ms | One result gzip bytes |
| ----------------------------------- | ------------: | ------------: | --------------------: |
| Stock recent price                  |          2.78 |          1.11 |                 1,811 |
| Stock recent scored                 |      2,144.32 |          2.30 |                 2,295 |
| Regional ETF recent price           |          5.55 |          0.38 |                 1,849 |
| Regional ETF recent M0/index        |         37.92 |          0.43 |                 3,439 |
| Domestic-sector ETF recent M0/index |        715.76 |          0.48 |                 3,478 |
| Regional ETF full M0/index          |        230.56 |          1.53 |                33,846 |
| Domestic-sector ETF full M0/index   |      4,641.67 |          1.62 |                33,765 |
| Stock full scored                   |     16,991.59 |          1.95 |                21,678 |

Each profiled cold bundle used one storage read and one write; each warm bundle used one read and zero writes. Client regression tests establish two independent recent requests (price + M0/index), one coalesced source-metadata lookup, no browser raw-source download, and no full-history request on initial open. Actual deployment latency, authentication, network traffic, and real-source volume are not represented by the local profile.

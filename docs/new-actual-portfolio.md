# 2026-10-12 신규 실제 운용 연결

## 범위

포트폴리오 화면은 2026-10-12 이후 신규 운용분만 관리한다. 기존 보유·누적 체결·미체결 신호·옛 자금 설정 화면은 표시하지 않는다. 과거 원본은 삭제하지 않으며, 사용자는 기존 내역을 Notion에서 확인한다. Notion에만 반영한 과거 미국 매도를 홈페이지에 복제하거나 가상 매도로 입력하지 않는다. 모델은 Shadow에서 계속 독립적으로 관리한다.

이 변경은 실제 체결을 사용자가 기록하는 소프트웨어 연결이다. 증권사 주문, 매도, 송금, Notion 자동 수입 또는 실계좌 데이터 변경을 수행하지 않는다.

포트폴리오와 Shadow의 화면상 비교 시작일은 모두 2026-10-12다. 다른 시작점의 누적 원장 카드나 옛 원장 진입 링크를 포트폴리오에 두지 않는다. 비교 시작일이 같아도 실제 입금·체결 날짜·가격·비용을 모델에 맞춰 조작하지 않으며 차이를 명시한다.

## 거래와 성과 연결

- 기존 owner-scoped `portfolio_ledgers` / `us_actual_portfolio_ledgers` 문서와 canonical 원장을 그대로 사용한다.
- 체결 원본과 명시적 신규 배정 메타데이터를 하나의 문서 CAS로 저장한다. 기존 DB trigger가 원본 체결 추가·정정·취소를 append-only canonical 이력으로 반영한다.
- `newActualPortfolio` JSON 메타데이터에는 고정 시리즈 ID, 체결 ID별 신규 수량·금액·비용·증빙 식별자, 현금 흐름과 변경 감사 이력만 저장한다.
- 날짜만으로 신규 거래를 판별하지 않는다. 명시적 배정이 없는 체결은 10/12 이후라도 제외한다. 기존 기록 ID를 새 구간으로 옮기는 입력은 거절한다.
- 새로운 체결은 이전 신호·주문을 승계하지 않는다. 모델의 수량·현금도 사용하지 않는다.
- 같은 종목의 옛 보유와 신규 보유는 신규 배정분만으로 원가를 계산한다. 신규 부분매도는 신규 가중평균 원가를 사용하고 전량 매도 시 잔여 원가를 모두 소진한다.
- 기존·신규 혼합 체결은 전체 원본과 신규 수량·거래금액·실제 비용을 따로 입력한다. 자동 FIFO나 임의 비례 배분은 없다. 신규 보유를 넘는 매도는 거절한다.
- 혼합 체결 원본은 이 화면에서 삭제하거나 경제적 필드를 수정할 수 없다. 원본 변경이 필요한 경우 별도 대조가 필요하다. 이후 배정을 전량으로 정정해도 과거 혼합 이력이 있으면 원본 보호가 유지된다.
- 체결 근거 식별자 중복을 막고, 요청 UUID별 지문으로 응답 소실 후 같은 요청을 재처리하지 않는다.

## 현금·손익 정책

- 한국주식과 ETF는 하나의 KRW 현금 풀을 공유한다. 동일한 실제 원화 배정은 한 번만 입력한다. USD는 별도 풀이다.
- 저장된 총 운용계획 금액과 기존 `actualCapital` / `etfCapital` / 미국 `capital`은 입금이나 NAV로 사용하지 않는다.
- 실제 발생한 배정·입금·출금·배당·이자·별도 비용·세금만 명시적으로 기록한다. 체결 비용에 이미 포함한 금액은 현금 비용으로 반복 입력하지 않는다.
- 기존 보유 매도대금이 실제로 새 운용분에 재배정되면 `DEPOSIT`으로 입력한다. 외부 입출금은 투자손익에 포함하지 않는다.
- 배정이 미확정이어도 실제 체결과 보유·실현손익은 기록한다. 현금·NAV·총손익·수익률은 준비 중으로 둔다.
- 거래·현금 흐름을 합친 과거 어느 날의 기말 현금이라도 음수면 자금 부족 상태로 표시하며, 거래 자체는 보존한다. 이는 증권사 잔고·결제금·장중 주문 가능 금액이 아니다.
- 확정된 하나의 최초 배정과 추가 외부 흐름이 없는 경우에만 통화별 단순 수익률을 계산한다. 추가 입출금이 있으면 순입출금 조정 금액 손익은 계산하되 시간가중 수익률은 미확정으로 둔다.
- 검증된 환율·환전·배정 기준 연결 전에는 USD를 임의 환산하지 않고 원화 합산 성과·수익률을 미확정으로 둔다. 화면은 KRW/USD 통화별 수치를 제공한다.

## 평가가격과 현재 한계

- 국내·ETF는 기존 해시 검증 원천데이터 읽기 함수를 사용한다. 미국은 기존 미국 평가가격 캐시를 읽는다. 모델 재실행이나 소스 수정 없이 읽기만 한다.
- 체결가를 현재가로 대신 사용하지 않는다. 누락·미래·오래된 시세는 평가에 쓰지 않는다.
- 검증된 거래일 달력 연결 전에는 시장 현지 당일과 일치하는 가격만 현재 평가에 사용한다. 따라서 휴장일·장 시작 전·당일 데이터 미수신에는 보유·체결·실현손익을 유지하고 평가자산·수익률만 대기한다. 임의 휴일 추정은 하지 않는다.
- 화면은 매 저장과 재조회 때 계산되는 현재 투영이다. 이전 수동 JSON 경로는 더 이상 포트폴리오 화면에 노출하지 않는다. 별도의 일별 확정 NAV 스케줄러나 환율 자동 확정은 이번 범위에 포함되지 않는다.

## 안전성

- 신규 테이블·migration·RLS·권한 확대·service-role 키가 필요 없다.
- 서버는 검증된 로그인 계정 ID만 사용한다. 클라이언트의 owner/source 지정 필드는 거절한다.
- 열었을 때의 원장 revision과 요청 ID를 보존한다. 중복 클릭을 동기식으로 막고, 실패·응답 소실 시 자동 재시도하지 않는다.
- 저장 후 canonical 원장 readback을 확인한다. 불확실한 결과는 새로고침으로 확인하고 입력을 닫았다가 다시 열어야 한다.
- 계정 전환 시 이전 계정의 응답·캐시가 새 화면에 반영되지 않는다.
- 현금 정정·취소는 before/after 감사 이력을 남긴다. 실제 체결 취소는 canonical void revision을 남기며 증권사 매도를 만들지 않는다.

- 신규 단위·서버·입력·인증·실제 UI 핸들러: 98개 통과.

- 독립 검토의 오래된 전체 시세, 혼합 원본 변경, 혼합→전량 재배정→취소 우회 재현 3개 통과.
- 기존 canonical migration만 적용한 격리 PGlite 검증 통과: 체결·메타데이터 동시 저장, 원본 보존, 현금 메타데이터, 체결 정정·void 이력, 다른 소유자 읽기·쓰기 차단. 신규 migration 없음.
- TypeScript 전체 검사, 변경 범위 ESLint, `git diff --check`, production build 통과.

- 운영 계좌·Notion 데이터 쓰기, 원격 push, PR, 병합·배포는 이 검증에 포함되지 않는다.

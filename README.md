# CloudTrend

### 2026-09-10: 전체 기술점수와 진입 위험 검증

- 주식·ETF 상세 가격 차트 및 최근 점수 차트는 52주 신고가를 포함한 9.5점 원점수를 표시합니다. 252거래일과 전체 항목이 확보되기 전 및 자료 누락 구간은 `null`로 남기며 선을 연결하지 않습니다.
- 백테스트 복합점수·랭킹은 현재 기본 배점(1/1/1.5/1/0.5/2.5/2)을 고정합니다. 피처별 영향도 실험 설정은 복합 기술점수를 바꾸지 않습니다. 5/6/7/8/9점 진입을 비교합니다.
- 수익률은 신호 다음 거래일 시가 진입 → h번째 거래일 종가 청산으로 계산합니다. 왕복 비용 입력은 bps 단위이며 기본값은 0입니다.
- 일별 점수 구간별 성과 및 신규 돌파/지속 2~5일/지속 6일 이상/시작 불명 비교에 평균·중앙·승률·시장초과·P5·만기 10% 손실 비율·보유 도중 10%/20% 하락 비율을 제공합니다. 누락된 벤치마크와 저가 경로의 표본 수는 별도로 표시합니다.
- 자료 첫날부터 이미 높은 점수인 경우 신규 진입으로 가정하지 않습니다. 자료 공백 이후에도 돌파 시작을 확인할 수 없으면 ‘시작 불명’입니다.
- 일별 분석은 관측 간격과 무관하게 모든 거래일을 판정합니다. 기존 피처 표는 선택한 관측 그리드를 유지합니다. PDF는 일별 분석의 전체 보유기간 및 ALL/OOS 표를 모두 출력합니다.
- ALL/OOS는 중첩 전방수익률의 기술통계이며 독립 거래·실제 포트폴리오 성과가 아닙니다. OOS를 보고 가중치를 선택했다면 새로운 미사용 기간 검증이 필요합니다. 2026-09-09 PDF는 볼린저 2점(총 10점) 및 가용항목 100점 환산 방식이어서 현재 결과와 직접 비교할 수 없습니다.

- 제안 전략 비교는 6/7/8점 진입, 신고가 근접(상태·신규 충족), RISK_ON, 이격 15% 미만, −5/−7% 손절, 4점 미만 다음 시가 청산을 단독/조합으로 검증합니다. 종목별 중복 보유를 금지하고, 손절가 아래 시가 갭을 실제 시가 손실로 반영합니다. 시장별 및 ALL/OOS의 거래 수·평균/중앙·승률·손익비·보유일수·청산 사유를 비교합니다. 이는 계좌 전체의 자본배분 시뮬레이션이 아닙니다.

검증: `node --test tests/chart-history.test.mjs tests/score-diagnostics.test.mjs` (Node 24+).

국내·미국 주식과 ETF의 종가 데이터를 바탕으로 시장 상태, 추세 신호, 섹터 로테이션과 종목별 점수를 계산하는 **규칙 기반 리서치 도구**입니다.

CloudTrend는 사용자가 직접 준비한 일봉 데이터를 브라우저에서 분석합니다. 결과뿐 아니라 각 점수의 조건, 산정 가능 점수, 데이터 누락과 실격 사유를 함께 보여주며, 투자 판단이나 자동 주문을 대신하지 않습니다.

## 현재 제공 기능

### 한국 시장

- CSV·JSON 업로드 또는 텍스트 붙여넣기를 통한 분석 데이터 입력
- KOSPI·KOSDAQ 시장 게이트와 Risk-On / Neutral / Risk-Off 판정
- 국내 주식 및 ETF 분리 스크리닝
- 종목별 Technical, Priority, Fundamental 또는 ETF Health 점수
- 실격 필터, 데이터 누락 항목, 경고 신호 및 점수 계산 근거 표시
- 종목 상세 차트: OHLC, 이동평균, 볼린저밴드, 일목균형표, 거래량
- 가격 리더십과 자금 흐름을 분리한 섹터 로테이션 분석
- 포지션 사이징 계산기와 스크리닝 이력 저장
- 데이터 품질·커버리지 점검
- 주요 결과 PDF 및 표 데이터 CSV 내보내기

### 미국 시장

- 별도 US 데이터 입력 및 스크리닝
- SPY·QQQ·IWM 기반 Market Policy v1
- 11개 GICS 섹터 프록시 ETF 기반 섹터 게이트
- 미국 주식·ETF의 Technical, Priority, ETF Health 점수
- 종목 상세 화면과 데이터 커버리지 표시
- 토스증권 Open API 데이터를 로컬에서 수집하기 위한 Jupyter 예제 코드 제공

### 백테스트

- 직접 업로드한 별도 백테스트 데이터 또는 한국 스크리닝 데이터 사용
- 70점 Onset 당일의 1일 점수 변동을 0~~5p, 5~~10p, 10~20p, 20p 이상으로 나눈 대표전략 성과 비교
- 실행마다 데이터 버전·Git 코드 버전·설정·전체 결과를 하나의 재현성 번들로 Supabase에 저장
- 5·10·20·30·40·60거래일 forward return 동시 분석
- 피처 신호·비신호 집단의 평균/중앙값 수익률, 승률, edge 및 t값 비교
- edge decay, 점수 구간, 관측 간격, 진입 임계값, 거래량·과열 기준 민감도 분석
- 피처 상관행렬과 수익률 분포 확인
- 관측 시점 이후 데이터는 forward return 계산에만 사용하여 look-ahead 방지
- 수수료, 세금, 슬리피지는 미반영

## 사용 흐름

1. **데이터·산식** 화면에서 한국 시장 CSV·JSON을 업로드하거나 데이터를 붙여넣습니다.
2. 파싱 결과와 경고를 확인하고 **스크리닝 시작**을 누릅니다.
3. 대시보드, 주식·ETF 스크리너, 섹터, 종목 상세 및 데이터 상태 화면에서 결과를 확인합니다.
4. 필요한 경우 산식과 가중치를 조정해 다시 계산합니다.
5. **백테스트** 화면에서 별도 장기 일봉을 입력해 피처 설명력과 임계값 민감도를 검증합니다.
6. 미국 시장은 **US 시장·데이터** 화면에서 데이터를 별도로 입력해 실행합니다.

입력 CSV는 Supabase의 비공개 Storage에 계정별로 저장됩니다. 국내·미국 데이터는 각각 최신 파일을 유지하고, 백테스트 데이터는 파일당 45MB 이하로 여러 개를 저장해 실행 시 합칩니다. 같은 계정으로 로그인하면 다른 기기에서도 불러옵니다. 이미 열린 화면은 상단의 최신 데이터 불러오기 버튼으로 갱신합니다. 계산은 브라우저에서 수행합니다.

국내 스크리닝 이력은 Supabase `screening_history` 테이블에 날짜별 마지막 결과로 저장됩니다. 최근 90개 날짜를 유지하며 날짜당 1MB를 넘는 결과는 오류로 표시합니다. RLS로 본인 계정의 파일과 이력만 접근할 수 있습니다. 기존 브라우저 데이터는 자동 이전하지 않으므로 원본 CSV를 다시 업로드해야 합니다.

Supabase Free 플랜을 유지합니다. 유료 기능·브랜치는 사용하지 않습니다. Free의 전체 프로젝트 한도(Storage 1GB, DB 500MB, 일반 egress 5GB)는 계정별 앱 제한과 별개입니다. 한도 도달 시 서비스 제한이 발생할 수 있으며 유료 전환은 자동으로 수행하지 않습니다. https://supabase.com/pricing

앱의 회원가입 후 확인 이메일을 확인하고 로그인하세요. Supabase 기본 이메일 발송기는 프로젝트 팀 이메일에 제한될 수 있습니다. 발송이 거부되면 Supabase Auth 설정을 확인해야 합니다. `VITE_SUPABASE_URL` 및 `VITE_SUPABASE_PUBLISHABLE_KEY`로 연결을 재정의할 수 있습니다. 기본값은 이 프로젝트의 공개 클라이언트 키이며 비밀키는 사용하지 않습니다. 비밀번호는 앱 화면에서만 입력합니다.

## 한국 데이터 형식

CSV 헤더 예시:

```csv
symbol,name,market,date,open,high,low,close,volume,tradingValue
005930,삼성전자,KOSPI,2026-08-31,71000,72000,70800,71800,12345678,886000000000
KOSPI,코스피,INDEX,2026-08-31,2650.1,2662.3,2644.0,2658.7,0,0
```

핵심 필드:

| 필드                  | 설명                                 |
| --------------------- | ------------------------------------ |
| `symbol`              | 종목코드 또는 지수코드               |
| `name`                | 종목명                               |
| `market`              | `KOSPI`, `KOSDAQ`, `ETF`, `INDEX` 등 |
| `date`                | 거래일                               |
| `open/high/low/close` | 일봉 OHLC                            |
| `volume`              | 거래량                               |
| `tradingValue`        | 거래대금                             |

정확한 시장·섹터·우선순위 판정을 위해서는 지수 일봉, 시가총액, 외국인·기관 순매수, 종목 구분 및 섹터 정보도 함께 넣는 것이 좋습니다. 제공되지 않은 값은 임의의 0으로 채우지 말고 비워 두어야 데이터 커버리지가 왜곡되지 않습니다.

## 현재 점수 체계

### Technical Signal Score V3 — 기본 7점

| 항목                  | 기본 배점 |
| --------------------- | --------: |
| 종가 > 일목 구름 상단 |       2.0 |
| MA20 > MA60 > MA120   |       2.0 |
| Momentum Confirmation |       1.5 |
| 볼린저 상단 돌파      |       1.0 |
| 고가 마감 거래량      |       0.5 |

Momentum Confirmation은 다음 세 조건의 충족 개수에 따라 0.5점씩 반영합니다.

- 전환선 > 기준선
- MA20 상승
- 20일 수익률 양수

볼린저 상단 돌파는 Head Fake 경고 시 충족으로 처리하지 않습니다. 고가 마감 거래량은 거래량 비율과 CLV 기준을 함께 사용합니다.

### 기타 점수와 필터

- **Priority Score**: 지수 편입, 외국인 수급, 실적 모멘텀, 신고가 근접성, 규모 등
- **Fundamental Score**: 주식의 수익성·성장성·재무건전성·밸류에이션
- **ETF Health Score**: ETF의 AUM, 거래대금, 괴리율 등 상품 건전성
- **Market / Sector Score**: 시장 게이트와 섹터 상대강도·수급·breadth
- **Universe Filter**: 거래정지, 관리·경고, 우선주, 데이터 기간, 가격, 시가총액, 레버리지·인버스 ETF 등

데이터가 없는 규칙은 0점이나 미달로 단정하지 않고 **데이터 없음**으로 분리합니다. 점수는 산정 가능한 항목을 기준으로 정규화하며 데이터 완전성을 별도로 표시합니다. 임계값과 가중치는 데이터·산식 화면에서 조정할 수 있습니다.

## 재현 가능한 백테스트 실행

웹의 **백테스트 실행** 버튼은 현재 로그인 계정의 비공개 Storage에
`backtest/runs/<실행 ID>.json`을 자동 저장합니다. 이 번들에는 입력 파일 목록으로 만든 데이터
버전, 배포 Git SHA, 실제 엔진 설정, 점수 변동 구간 정의와 전체 결과가 함께 들어갑니다.

동일 엔진을 로컬 파일로 실행하려면 다음 명령을 사용합니다.

```bash
npm run backtest:run -- --input data/part-1.csv --input data/part-2.csv
```

신뢰된 서버나 GitHub Actions에서 Supabase의 비공개 백테스트 파일을 직접 읽고 결과까지 다시
업로드하려면 서버 전용 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 환경변수로 설정합니다.
서비스 역할 키는 브라우저나 `VITE_*` 환경변수에 넣으면 안 됩니다.

```bash
npm run backtest:run -- --supabase-user-id <USER_UUID> --upload
```

기본 설정은 `config/backtest.score-change.json`, 로컬 산출물은
`backtest-runs/<실행 ID>/bundle.json`과 `score-change-summary.json`입니다.

## 환경변수와 API 키

일반적인 수동 데이터 입력·브라우저 분석에는 API 키가 필요하지 않습니다.

저장소에는 토스증권 Open API 서버 연동 코드와 로컬 데이터 수집 예제가 포함되어 있습니다. 이를 사용할 경우 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET` 등의 자격증명은 로컬 또는 배포 환경의 서버 전용 환경변수로 관리하고, 브라우저 코드나 저장소에 커밋하지 마세요.

## 현재 제약사항

- 데이터 수집과 갱신은 완전 자동화되어 있지 않으며 사용자가 분석 데이터를 준비해야 합니다.
- 재무 스냅샷과 ETF 메타데이터가 입력 데이터에 없으면 해당 점수는 제한적으로 계산됩니다.
- 시장·섹터 판정에 필요한 지수나 수급 데이터가 없으면 일부 조건은 판단 보류됩니다.
- 점수 설정 등 브라우저별 개인 설정은 별도입니다. CSV와 국내 스크리닝 이력은 계정 단위로 공유됩니다.
- 백테스트 표본은 중첩될 수 있으며 통계량은 전략의 미래 성과를 보장하지 않습니다.
- 자동 주문, 증권계좌 연결 및 매매 실행 기능은 제공하지 않습니다.

## 투자 유의사항

CloudTrend의 점수, 등급, 관심 후보, 리테스트 대기, 관망 및 청산 점검 등의 표시는 정해진 규칙의 계산 결과입니다. 이는 투자 자문이나 매수·매도 권유가 아니며, 데이터 오류와 시장 변동을 포함한 최종 투자 판단과 책임은 이용자에게 있습니다.

주식 기술점수는 백테스트와 동일한 Vf 7개 피처(기본 9.5점)이며, 상세·목록·CSV·점수 추이에 같은 점수를 사용합니다. 순위와 등급은 산정 가능한 피처의 배점으로 정규화한 점수를 사용합니다. 당일 거래대금은 장중 수집을 고려해 주식 실격 조건에서 제외하며, ETF의 20일 평균 거래대금 기준은 유지합니다.
